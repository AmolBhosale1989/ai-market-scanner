# PostgreSQL 18 lineage contract execution — TEST ONLY

This validation branch is based on frozen PR #84 commit
`25c2c8bfca2cb648bf265e0baed5ffe25a6fec69`. It does not modify that branch,
main, scanner runtime code, production migrations, GitHub workflow definitions,
Render configuration, or the production warehouse. Do not merge or deploy this
branch as a production fix.

## Why this branch exists

The local authoring workspace has no PostgreSQL server/driver and cannot resolve
package-download hosts. Existing repository CI runs PostgreSQL 16, while the
Render database reports major version 18. The ordinary pull-request CI event can
execute the pending database contracts without workflow_dispatch access.

`tests/test_lineage_pg18_contract_gate.py` invokes `run_docker_pg18.py` from the
existing CI job. The runner pulls the official postgres:18 image, logs its digest,
then starts that exact image ID as a separate throwaway container. The container
has network mode `none`, no published ports, no TCP listener, transient database
storage, and one private host Unix socket. It is removed in finally cleanup.
The contract subprocess receives no DATABASE_URL, PG* variables, Telegram keys,
or production provider credentials. It uses only the explicit local socket,
fixed throwaway database `lineage_gate_test`, and test user `lineage_test`.
The CI PostgreSQL 16 service and its test database are not the contract target.

## Test input integrity

The seven inputs in `contract_inputs.sha256.json` are copied byte-for-byte from
previously supplied `lineage_db_gate.zip`. Their hashes are checked before database
startup. They include the original DDL, all 18 pending contract methods, reduced
schema fixture, persistence adapter, and supporting lineage modules. The original
18 tests are not replaced with mocked SQL tests. Their old source docstrings
remain intact; execution status comes from the current CI log, not those comments.

The test runner verifies major version 18, database/user identity, Unix transport,
empty listen_addresses, and network isolation. It prints the real server version,
psycopg version, each test result, final count/duration, and container cleanup.
An exit code alone is insufficient: PASS also requires `Ran 18 tests` and `OK`.
CI prerequisite or integrity failures are failures, never silent skips.
Local execution is opt-in with `LINEAGE_LOCAL_DOCKER_TEST=1` and still creates a
new container; arbitrary connection strings are never accepted.

## What a pass means

It demonstrates the tested SQL/adapter behavior on a real PostgreSQL 18 engine
using the reduced synthetic public schema: original evidence retention after
rollback, atomic publication/intents, committed-only visibility, append-only
records, binding enforcement, delayed-commit exclusion, pinned catalogue
revisions, deferred deadline/certificate checks, concurrent queue claims,
late-intent rejection, application acknowledgements, and terminal uncertainty.

It does NOT establish compatibility with every real migration/partition/role,
correct producer dependency completeness, ranking separation, a fully fenced
external dispatcher, production-scale latency, Render UI correctness, or the live
Feeder/Engine overlap. No external messages are sent. Fixture certificates are
not generated by the real trading freshness authority. The test database owner
can perform DDL; least-privilege deployment remains a separate acceptance gate.

## Delivery semantics

DELIVERY_UNKNOWN is quarantined to prevent blind automatic replay. This can lose
an alert. It is not an exactly-once or at-least-once external-delivery guarantee,
and the tests do not prove at-most-once transport behavior under every worker or
provider failure. No Telegram provider-side idempotency mechanism is assumed.

## Evidence required

Use the completed CI log's `LINEAGE_PG18_SERVER`,
`LINEAGE_PG18_CONTRACT_RESULT`, and `LINEAGE_PG18_CLEANUP` records. Until those
are observed, the database contracts remain NOT VERIFIED. A successful ordinary
repository CI run without the explicit 18-test PG18 result does not pass this gate.
