This does **not** establish that every feature works or that market-open freshness and recovery are reliable. This audit found concrete correctness and presentation defects and adds the repairs and regression tests listed below.

## Confirmed defects repaired in this change

1. **False production acceptance evidence.** The production CLI ran a fixed September 18 fixture and printed PASS without examining the active run. It now verifies the actual full/live dependency graph, every required dataset's row count and hash, current-run snapshot provenance, anchor timing and live observation timestamps. Publication also rejects missing stages, not only nonpassing recorded stages.
2. **Mixed V4 catalyst evidence.** The worker exported all retained event types as catalysts. Price snapshots, options and state transitions inflated catalyst counts and produced `nan` labels. Only recent actual catalyst events now enter this calculation/export; all original event history remains intact. Future news is rejected rather than clamped to age zero, and payloads cannot replace the event envelope's ticker/time.
3. **Incomplete observation-time validation.** Final publication and dashboard read-time checks previously covered only momentum, rotation leaders and sector rotation. They now also cover intraday-live, V3, V4 and live themes using the source bar timestamps, not calculation timestamps. Missing datasets and invalid/stale/future/unfinished observations still block.
4. **Unfinished bar accepted as fresh.** The warehouse checked whether the bar start was in the future, allowing a still-open bar whose start was in the past. The shared gate/consumer rule now requires the bar end to be no later than the validation clock. Existing tests that incorrectly expected an unfinished 15:05–15:10 bar to pass at 15:09 were corrected.
5. **Optional missing themes received a live score.** Missing returns were filled with zero and used to rank a quarantined ETF. Live rankings now contain only eligible fresh ETFs. The existing minimum coverage and mandatory benchmarks remain unchanged, and the dashboard discloses excluded ETF names.
6. **Market-closed results presented as current buys.** The live UI showed four current actionable/confirmed buys on Saturday. Current action counts and recommendation cards now depend on the actual NYSE calendar, including weekends, holidays and early closes. Last-session results remain explicitly labelled research. Theme tables display the live score that actually determines their live rank.
7. **The 30-minute price move used a 25-minute or variable window.** Sector rotation and broad breakout used six close prices instead of observations exactly thirty minutes apart. Both now use exact same-session endpoints. Missing endpoints remain unavailable; they are never forward-filled or replaced by another time. Rotation shows `NOT_READY_30M` without a score, rank or leader flag. This also fixes Python's `min(100, NaN)` producing a spurious maximum score. The opening session cannot produce this indicator until enough observed history exists.
8. **Relative volume compared different clock times.** Broad breakout and momentum used the number of today's returned bars to truncate previous sessions. Sparse/omitted buckets shifted the reference window. They now sum observed historical volume through the same NY clock time, preserving their respective two- and three-session baselines and existing decision thresholds.

## Open findings and operational limits

- **Core news/earnings integration is incomplete.** `scanner.catalysts.analyze_catalyst()` requests `catalyst_context`, but `warehouse.request_dataset()` deliberately raises `WAREHOUSE_DATASET_NOT_MIGRATED`. Published candidates show `catalyst_status=ERROR`. This is separate from the V4 news adapter; synthetic or cached unrelated news must not be substituted to hide it.
- **Independent recovery is not deployed.** Production still runs through GitHub Actions with workflow concurrency and success-only continuation. Lease primitives/tests exist, but the production entry point is not using the heartbeat/fencing supervisor, and an independently hosted coverage watchdog is not verified. A failing scan can still stop continuation until another trigger arrives.
- **Market-open operation needs observation.** Run #38 completed after close; freshness is measured against the latest exchange close on weekends. No claim is made that this run proves all symbols will meet the ten-minute consumer contract during trading or that scheduler delays are repaired.
- **Historical research is intentionally carried forward in live refreshes.** New dataset versions can contain unchanged research from the preceding full publication. Publication time is not the observation time or a new model fit. Live-family timestamps and provenance must be checked separately.
- **Strategy evidence is insufficient.** The baseline validation gate is `PAPER_VALIDATION`, `ready_for_real_money=false`, with four closed signals versus the configured minimum of thirty and no fitted probability-calibration sample. Bar-derived order flow is not bid/ask tape or Level 2. No profitability conclusion follows from pipeline tests.
- **News classification is heuristic.** The V4 adapter uses keyword matches, not a validated semantic news model. For example, a headline about an investigation closing can still receive a negative investigation keyword veto. Published news retains `review_required=true`; it is not a verified interpretation of economic impact. The mixed-event and timestamp defects were repaired, but headline interpretation is not certified by this audit.
- **Delivery limitations remain visible.** Telegram is not configured in baseline monitor health. The Render web service is free and was observed waking from sleep before the app loaded; the paid PostgreSQL plan does not remove web-service cold starts. No plan, service or spending was changed.

## Validation and follow-through

Regression coverage includes mixed catalyst event history, real negative-news veto retention, future news, every live dataset's independent expiry, incomplete candles, full/live stage completeness, dependency ordering with valid parallel execution, and PostgreSQL corruption/wrong-run/missing-stage rejection. PostgreSQL tests run in the repository CI service database, not production.

Release verification must inspect CI results, deploy the reviewed commit, run exactly one new production scan if none is active, inspect its actual acceptance output and immutable publication, and confirm Render shows that same publication with market-appropriate labels. A future regular market session and independently supervised recovery still need separate operational evidence.
